# Block 2: 공개

> **Phase A 시작 시 그대로 출력한다:**
> ```
> 📖 공식 문서: https://docs.github.com/ko/pages/getting-started-with-github-pages/creating-a-github-pages-site
> ```

## EXPLAIN

### 1. 용어

| 용어 | 뜻 |
|---|---|
| GitHub 저장소 (public) | 누구나 볼 수 있는 온라인 폴더. 올린 파일은 전부 공개된다 |
| GitHub Pages | 저장소의 `index.html`을 웹 주소(`https://내아이디.github.io/저장소이름/`)로 보여 주는 기능 |

### 2. 왜 공개 전에 점검하는가

| 기준 | 폴더째 올리기 | 고른 파일만 올리기 |
|---|---|---|
| 올라가는 것 | 작업 중 파일·메모·내부 자료까지 | 그래프 `index.html`과 설명 README만 |
| 데이터 표기 | 가상인지 알 수 없다 | 그래프에 "가상 데이터(실습용)" 표기 — 원본 강의 제출 기준 "합성·예시 데이터는 '예시'로 명시" |
| 비밀값 | 토큰이 섞여도 모른다 | 올리기 전에 Claude Code가 훑는다 |

보안 수칙: 비밀번호·토큰은 대화창에 쓰지 않는다. 로그인은 브라우저 창에서 내가 직접 한다. 회사 내부 데이터는 공개 저장소에 올리지 않는다.

### 3. 케이스

5일차 덱은 오늘의 분석이 6일차 통합 보고서의 "제조 역량" 조각이 된다고 말한다. 그래프를 주소 하나로 남겨 두면 동료에게 보여 줄 때도, 6일차에 다시 쓸 때도 파일을 찾을 필요가 없다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
pdm-lite 폴더의 진동 그래프를 GitHub Pages로 공개해 줘.
1. gh 로 GitHub 로그인 상태를 확인해 줘. 안 돼 있으면 브라우저 로그인용 일회용 코드만 알려 줘. 비밀번호나 토큰을 나에게 묻지 마.
2. 공개하기 전에 index.html 에 비밀값·개인정보가 없는지, "가상 데이터(실습용)" 표기가 있는지 확인해 줘.
3. 확인 결과를 보여 주고 "공개해도 될까요?"라고 나에게 물어봐. 내가 좋다고 할 때만 다음으로 가.
4. public 저장소 pdm-lite-dashboard 를 만들고 index.html 과 짧은 README.md(무엇을 보여 주는 그래프인지, 데이터 출처: keerhee/kma-auto-genai-3-1 data/Day5 가상 데이터)만 올려 줘. 같은 이름 저장소가 있으면 덮어쓰지 말고 먼저 알려 줘.
5. GitHub Pages 를 main 브랜치 루트로 켜고, 주소가 열리는지 확인해서 알려 줘.
6. 동료에게 보낼 한 줄 메시지(주소 포함)를 써 줘. 메시지는 보내지 말고 보여만 줘.
```

사람이 직접 하는 일:

1. 1번에서 일회용 코드가 나오면 브라우저 창에서 코드를 입력하고 **Authorize**를 누른다.
2. 3번 질문에 공개 여부를 답한다.

### 확인할 것 (Phase B)

- `gh repo view pdm-lite-dashboard`로 저장소가 public이고 파일이 `index.html`, `README.md` 두 개뿐인지 본다.
- Pages 주소(`https://<아이디>.github.io/pdm-lite-dashboard/`)가 응답 200으로 열리는지 직접 확인한다. Pages는 처음 켠 뒤 1~2분 걸릴 수 있다.
- 공개된 페이지에 "가상 데이터(실습용)" 표기가 있는지 본다.

막히면 아래 후속 프롬프트를 준다.

```
GitHub Pages 주소가 안 열리는 원인을 찾아 줘. Pages 설정(브랜치·폴더)과 배포 상태를 확인하고, 고칠 것만 알려 줘.
```
