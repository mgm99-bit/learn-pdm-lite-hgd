## EXPLAIN

### 1. 오늘 쓰는 데이터

| 용어 | 뜻 |
|---|---|
| 다변수 센서 데이터 | 진동·온도·압력처럼 여러 변수를 동시에 시간 순으로 기록한 것 (5일차 덱 p12) |
| 설비A (프레스 메인모터) · 설비B (차체 용접로봇 감속기) | 오늘 비교할 설비 2대. 각 25시점, 20분 간격, 합계 50건 |
| 가상 데이터(실습용) | 원래 회사 내부 자료라 공개본이 없어 만든 실습용 값. 실제 기업의 자료가 아니다 |

### 2. 왜 단위부터 보는가

| 기준 | 바로 분석 | 단위·주기 먼저 확인 |
|---|---|---|
| 판단 | 섞인 단위가 '이상'처럼 보일 수 있다 | 같은 단위끼리 비교해 판단이 흔들리지 않는다 |
| 원본 덱 (p18) | — | "단위(℃, mm/s, bar)와 측정 주기를 먼저 확인한다 — 단위가 섞이면 이상 판단이 흔들린다" |

### 3. 케이스

원본 강의의 함정 데이터에는 온도 123.6이 섞여 있다. 그대로 보면 과열 같지만 ℉로 기록된 값이고, ℃로 바꾸면 50.9로 평소 값이다. 오늘 데이터는 단위가 통일된 파일이지만, 분석 전에 단위 확인부터 하는 습관을 여기서 들인다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다. Phase A 출력 직전에 `{SKILL_DIR}`를 이 스킬 폴더의 실제 경로로 바꿔 보여 준다.

```
예지보전 실습 준비를 해 줘.
1. 내 홈 폴더 아래에 pdm-lite 폴더를 만들어 줘(이미 있으면 그대로 써).
2. {SKILL_DIR}/assets/lab/sensor_50_virtual.csv 를 pdm-lite 폴더로 복사해 줘. 원본 파일은 고치지 마.
3. 복사한 파일에서 행 수, 설비 이름과 설비별 행 수, 열 이름(단위 포함), 측정 간격을 확인해 줘.
4. 확인 결과를 pdm-lite/env_check.txt 에 적고, 맨 위에 "가상 데이터(실습용)"라고 써 줘.
5. 나에게 비밀번호나 토큰을 묻지 마.
```

끝나면 데스크톱 앱에서 **새 세션 → Local → `pdm-lite` 폴더 선택**으로 작업 폴더 세션을 열고, 그 세션에서 `/learn-pdm-lite-hgd`를 불러 Block 1로 이어 가라고 안내한다.

### 확인할 것 (Phase B)

- `~/pdm-lite/sensor_50_virtual.csv`가 있고 데이터 행이 50개인지 파일을 직접 세어 본다.
- 설비가 2대이고 설비별 25행인지 본다.
- `env_check.txt`에 단위(mm/s · ℃ · bar)와 20분 간격, "가상 데이터(실습용)"가 적혀 있는지 본다.

막히면 아래 후속 프롬프트를 준다.

```
env_check.txt 내용이 원본 CSV와 다른 곳을 찾아 원인을 알려 줘. 파일을 지우지 말고 고칠 곳만 보여 줘.
```
